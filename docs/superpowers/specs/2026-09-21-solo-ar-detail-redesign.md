# WISTIA 1인 AR 축가 상세페이지 리디자인 설계

## 목표와 범위

`#/detail/solo`만 대상으로 오디오 재생 오류와 편집 레이아웃을 함께 교정한다. 다른 상품 상세·예약 라우트의 구조와 스타일은 바꾸지 않는다. 기준은 `그림1.png`, 누적 결정 문서의 최신 항목, 그리고 390×844·768×1024·1280×720 배포 화면 감사 결과다.

이번 변경은 `js/app.js`, `css/design.css`, `index.html`의 캐시 버전, 관련 브라우저 테스트를 중심으로 한다. 새 AI 이미지나 추상 장식은 만들지 않고 저장소의 실제 고객 영상·사진·후기·제작 과정 이미지만 사용한다.

## 편집 구조

페이지 바탕은 차콜에 가까운 검정으로 바꾸고, 그 위에 폭과 정렬이 다른 화이트·실버 편집 블록을 배치한다. HERO는 콘텐츠 폭을 모두 사용한다. AR 강점은 왼쪽 기준, 비교 섹션은 오른쪽 기준으로 미세하게 어긋나게 배치한다. 후기와 전문가 제작 이야기는 하나의 큰 화이트 지면으로 묶어 연속된 기사처럼 보이게 한다. 진행 과정과 AR 비율 체험은 별개의 장면으로 분리하며, 블록 사이 검정 여백을 충분히 둔다.

외곽 편집 블록은 직선 모서리를 기본으로 하고 사진·다이얼·인터랙션 요소에만 절제된 라운딩을 사용한다. 반응형 전환은 viewport가 아니라 `.solo-detail-scope`의 container query를 기준으로 한다.

## HERO

실제 고객 영상과 현재 카피를 유지한다. 영상 영역은 4:5 비율을 기본으로 하고, 430px 미만 컨테이너에서는 최소 높이 560px을 보장해 카피가 밀리지 않게 한다. `object-fit: cover`와 컨테이너 폭별 `object-position`을 명시해 인물의 얼굴·마이크·상반신이 유지되도록 한다. 하단 그라데이션은 본식 장면을 지나치게 어둡게 만들지 않는 범위에서 텍스트 뒤쪽만 강화한다.

실제 영상 표기와 재생·일시정지 아이콘은 상단 안전 영역에 고정한다. 제목 줄바꿈은 390px과 500px 컨테이너 각각에서 의도적으로 지정하고, 영상 하단 곡선은 유지하되 다음 블록과 72px 이상의 흰 호흡을 확보한다.

## AR 강점

컨테이너가 430px 이상이면 카피 55%, 중앙 여백 8%, 원형 인덱스 37%의 가로 편집 구조를 사용한다. 원형 UI는 180~200px 안에서 유지하고 모든 키워드는 전용 영역 안에서 줄바꿈한다. 430px 미만에서만 카피와 원형 인덱스를 세로로 배치한다.

강조 문장은 왼쪽 카피 영역을 넘지 않는 차콜 채움으로 처리한다. 원형 중앙에는 현재 마이크 아이콘을 유지하며, 자동 순환은 `prefers-reduced-motion`에서 중지한다.

## 후기와 전문가 제작 이야기

후기와 전문가 섹션을 하나의 화이트 편집 지면으로 묶는다. 후기의 실제 카카오톡 이미지와 기존 탐색 버튼은 유지한다.

전문가 패널은 클릭·탭 전용 35:65 확장 구조를 유지한다. 활성 패널 높이를 충분히 확보하고, 두 사진에 개별 `object-position`을 적용한다. 활성 패널 하단은 짙은 검정 그라데이션으로 직무·설명 전체가 항상 읽히게 하고 비활성 패널에는 핵심 직무만 남긴다. hover만으로 활성 패널이 바뀌지 않는다.

## 비교 섹션

각 비교 기준을 독립된 행으로 만든다. 행 상단에는 `01 준비 범위` 형식의 번호와 기준을 두고, 아래에는 옅은 회색의 `일반 제작`, 중앙 고정 화살표, 화이트·실버의 `WISTIA`를 배치한다. 화살표는 hover 여부와 관계없이 항상 보인다.

행 클릭에 따른 다른 행 흐림 효과는 제거한다. 얇은 실버 구분선과 색·타이포 위계만으로 비교를 읽게 하며, 340px 이상에서는 두 비교 셀을 2열로 유지하고 그 미만에서만 세로 전환한다.

## 진행 과정

현재 `main`의 7단계 가로 카드 슬라이더를 기반으로 완성한다. 01~06은 `assets/img/song-process`의 실제 이미지, 07은 `약 7일` 정보 카드로 유지한다. 인트로를 승인 문구인 `노래가 익숙하지 않아도 괜찮습니다. 녹음부터 보정까지 WISTIA가 완성합니다.`로 교체하고 두 번째 문장에 은은한 회색 형광펜 효과를 적용한다.

활성 카드는 크게, 다음 카드는 일부 노출한다. 마우스 드래그·트랙패드·모바일 스와이프·좌우 방향키를 지원하며 자동재생은 하지 않는다. 최초 힌트 모션은 한 번만 실행하고 reduced motion에서는 생략한다.

## AR 오디오와 실버 다이얼

### 음원 로딩과 상태

- `RATIO_SOURCES`는 브라우저용 16-bit mono `voice-*-web.wav`를 사용한다.
- 첫 화면에서는 현재 선택된 한 음원만 로드한다. 나머지는 사용자가 해당 비율을 선택할 때 로드하며, 자동 비교 버튼을 누르면 비교 시작 전에 세 음원을 병렬로 준비한다.
- UI는 선택 음원의 `canplay` 이후 활성화한다. `error`, fetch 실패, 재생 거부를 상태 문구와 비활성 상태로 표시한다.
- Blob URL과 진행 중 요청은 비율별로 캐시하고, 라우트 이탈 시 생성한 Blob URL을 해제한다.
- 사용자가 재생하지 않은 상태에서 비율만 바꾸면 자동 재생하지 않는다. 재생 중 전환하거나 자동 비교 중일 때만 새 음원을 이어 재생한다.
- 재생 위치는 정상 구간에서 유지한다. 음원이 끝났거나 남은 시간이 0.75초 미만이면 다음 전환은 0초부터 시작해 무음 종료를 방지한다.
- 전환은 한 `<audio>` 요소에서 짧은 fade-out/source 교체/fade-in으로 처리하고, 경쟁 전환은 토큰으로 취소한다.

### 다이얼 인터랙션

기본 range input을 제거한다. 중앙의 브러시드 실버 다이얼은 CSS의 radial·conic·repeating-linear-gradient와 그림자로 만들고, 주변에 30·50·70·100 네 버튼을 배치한다. 70 위에는 작은 `추천` 말풍선을 둔다.

눈금 버튼 클릭, 다이얼의 좌우 방향키, 포인터 드래그로 값을 바꿀 수 있게 한다. 접근성 트리에서는 하나의 명확한 비율 선택 그룹과 현재값 설명을 제공한다. 값 표기는 `70% · 자연스럽게`처럼 간결하게 유지한다.

얇은 재생선과 재생·음소거 버튼은 다이얼보다 낮은 시각 위계를 갖는다. 자동 비교는 작은 차콜 버튼으로 제공하며 사용자 조작 즉시 중단한다.

## CTA 정책

가격 이동은 헤더 아래 sticky CTA 하나만 유지한다. 솔로 상세페이지에서는 데스크톱 우측 중복 PRICE 버튼을 제거하고 CONTACT만 작은 보조 버튼으로 남긴다. 모바일에서는 콘텐츠를 덮는 fixed 카카오 버튼을 숨기고 FAQ 뒤와 푸터의 인라인 카카오 링크를 사용한다. 하단 fixed 가격 바와 FAQ 내부의 중복 가격 버튼은 제거한다.

## 오류 처리와 접근성

오디오 로드 실패 시 재생·자동 비교를 비활성화하고 재시도 가능한 문구를 제공한다. 비율 전환 중에는 마지막으로 성공한 음원을 유지한다. 이미지에는 실제 내용에 맞는 대체 텍스트를 유지한다.

모든 버튼은 44px 이상의 터치 목표를 확보하고 키보드 포커스를 표시한다. 모션은 transform과 opacity 위주로 제한하고 `prefers-reduced-motion`을 지원한다. 페이지 수평 스크롤은 허용하지 않되 진행 과정 레일 내부의 의도된 가로 스크롤만 허용한다.

## 테스트와 완료 기준

구현 전 기존 테스트를 새 요구사항에 맞춰 실패하도록 갱신한 뒤 코드를 수정한다.

- 네 `-web.wav` 경로와 HTTP 성공, 비어 있지 않은 파형을 확인한다.
- 첫 음원만으로 컨트롤이 활성화되고 currentTime이 실제로 증가하는지 확인한다.
- 30·50·70·100 전환, 일시정지 상태 보존, 끝 지점 초기화, 자동 비교 중단, 오류 UI를 검증한다.
- AR 강점의 430px container-query 전환, 비교표의 고정 화살표, 7단계 카드 및 키보드 이동, 전문가 35:65 전환을 검증한다.
- 390×844, 768×1024, 1280×720 실제 브라우저에서 HERO 크롭, 텍스트 겹침, CTA 가림, 수평 넘침과 주요 섹션을 시각 검수한다.
- 전체 기존 라우트 회귀 테스트와 JavaScript 구문 검사를 수행한다.

커밋·푸시·배포는 수행하지 않는다.
