# 기존 가계부 예약 일정 연결

## 이미 준비된 내용

- 기존 가계부 `녹음실 일정`은 수정하지 않음
- 확정 예약의 `방문일` 시작·종료 시간을 읽고 `취소 여부 = 취소` 및 지출 행은 제외
- 목·금·토·일 운영, 월·화·수 휴무
- 평일 할인 폐지, 활용 동의 할인 최대 1만원과 후기 페이백 최대 6만원은 별도 계산
- 기존 `위스티아 (매월정산 개선본)` → `가계부` → `녹음실 일정`만 읽음
- 별도 마감표와 `마감 해제` 체크는 사용하지 않음
- 홈페이지 API는 날짜·시간만 반환, 고객 이름·이메일·금액·사유는 반환하지 않음
- 홈페이지 문의는 예약 확정이 아님, 최종 확정은 기존 카카오톡 상담에서 진행

## 폐하께서 사용하실 방법

확정 예약은 지금처럼 [기존 가계부의 녹음실 일정](https://app.notion.com/p/0ba5b5f67b45836c8269017a43a15fcb)에 `방문일`의 시작·종료 시간을 입력
다른 표에 중복 입력할 필요 없음
예를 들어 2026년 10월 11일 17:00~19:00 예약은 그 시간과 겹치는 홈페이지 문의 시작 시간을 마감 처리 (30분 단위 시작 시간 기준 SOLO 16:30~18:30, DUET 15:30~18:30, 스토리 14:30~18:30 시작 마감)

날짜만 입력하거나 시작 시간을 넣고 종료 시간을 비우면 안전하게 해당 날짜 전체를 마감 처리하므로 종료 시간까지 입력할 것
SOLO 1시간, DUET 2시간, 스토리 3시간 전체 구간이 기존 예약과 겹치면 선택 불가
예약 취소는 기존 `취소 여부`를 `취소`로 설정
지출 및 삭제·보관한 기록은 마감 대상에서 제외

앞서 생성한 `홈페이지 예약 마감` 표는 현재 연결에서 제외했으며 노션에서 삭제한 것은 아님
개인 휴무를 가계부에 새 금융 기록으로 입력하도록 요구하지 않음

## 2026-10-08 실제 상태

- 연결: 기존 가계부 `녹음실 일정` 하나만 읽는 노션 읽기 전용 내부 연결 (쓰기 권한 없음, 노션 기록 수정 없음)
- 환경변수: Vercel Production·Preview 모두 등록 (`NOTION_BOOKING_TOKEN`은 Sensitive, 값 비공개)
- 배포 중 발견·수정한 문제
  - `ERR_REQUIRE_ESM`: Vercel이 `api/availability.js`를 CommonJS로 변환한 뒤 `.mjs` 라이브러리를 require하지 못해 500 발생 → `api/availability.js`를 CommonJS로 작성하고 `lib/notion-availability.mjs`는 동적 `import()`로 불러오도록 수정 (`vercel build` 결과물을 Node 20·22·24에서 직접 실행해 재현·확인)
  - `예약 가능 시간을 확인하고 있습니다` 멈춤: 첫 날짜 입력과 상품 전환(스토리→SOLO) 때 진행 중 조회가 취소되거나 응답이 늦으면 확인 중 상태에 머묾 → 같은 날짜 조회 공유, 30초 결과 재사용, 8초 시간 제한 후 카카오톡 확인 안내로 전환, 확인 중에는 시간 선택 불가, 문의 복사 직전에는 항상 새로 조회
- 2026-10-08 KST 미리보기 실제 노션 데이터 검수 통과, 운영 결과는 `tests/notion-booking-qa.md`에 기록

토큰을 재발급하면 Vercel의 `NOTION_BOOKING_TOKEN`만 교체하고 재배포할 것
연결 권한이 해제되면 API는 503을 반환하고 화면은 카카오톡 확인 안내로 전환됨(예약 가능으로 표시하지 않음)

API는 읽기 전용이며 요청마다 최신 노션 데이터를 조회
화면을 열어 둔 상태에서는 `예약 가능 시간 다시 확인`으로 갱신하며 창에 다시 돌아오거나 문의 복사 전에 재확인
노션 장애·권한 오류·설정 미완료 시 예약 가능이라고 단정하지 않고 카카오톡 확인 필요로 안내
일정 조회 실패 중에도 희망 일정 문의 자체는 가능하며, 복사 내용에는 희망 일정/상담 확정 구분을 표시
동시 예약을 확정하는 결제 시스템이 아니므로 가계부에 입력하기 전 최종 예약 충돌 확인은 기존 상담 절차대로 유지

공식 자료: [내부 연결](https://developers.notion.com/guides/get-started/internal-connections), [데이터 소스 조회](https://developers.notion.com/reference/query-a-data-source)

## 문의 달력 범위 조회 (2026-10-08)

- `GET /api/availability?from=YYYY-MM-DD&to=YYYY-MM-DD`: 양 끝 날짜 포함 최대 42일. 날짜 누락·역순·초과·`date`와 혼용은 400.
- 응답: `{ok, from, to, timeZone, operatingDays, blocks: [{start, end}], checkedAt}`. 개인정보 없이 시간 구간만 반환하며 마지막 날짜의 늦은 시작 시간 계산을 위해 다음 날 구간까지 포함한다.
- 기존 `?date=` 응답 형태는 유지한다. 범위당 기존 가계부를 한 번 읽는다(스키마 확인 및 필요한 페이지네이션 포함). 취소·지출·보관/휴지통 제외, 날짜만 있거나 종료 없는 방문일 전일 마감 규칙은 동일하다.
- 달력은 월 범위를 조회하고 00:00~24:00 KST 전일 마감 또는 선택 상품의 시작 가능 시간 없음이면 회색 `마감`/disabled로 표시한다. 부분 예약은 가능한 시작 시간이 남아 있으면 선택할 수 있다.
- 상품 변경은 범위 결과를 공유한다. 범위 실패·8초 초과·잘못된 응답은 마감 근거로 쓰지 않고 날짜 선택 후 기존 하루 조회를 수행한다. 하루 조회 실패는 카카오톡 확인 안내로 끝나며 복사 전 강제 재조회는 유지한다.
- `api/availability.js`는 CommonJS이며 핸들러에서 `.mjs`를 native dynamic import한다. 노션 스키마/조회/페이지네이션은 전체 8초 제한을 공유한다.
